# Дизайн: настоящая пагинация (отдельные листы A4) — #1

Статус: **РЕАЛИЗОВАНО подходом №1** (v0.1.45, 2026-07-05) — визуально верифицировано.
Подход «мульти-NSTextView» (ниже) был отклонён; работающее решение — единый NSTextView
+ `PaginatedTextContainer` (переопределение `lineFragmentRect`).

## ✅ РАБОТАЮЩЕЕ РЕШЕНИЕ (v0.1.45): подход №1

Один `NSTextView` + один `PaginatedTextContainer: NSTextContainer` (файл
`PaginatedTextContainer.swift`). Пагинация — через переопределение
`lineFragmentRect(forProposedRect:at:writingDirection:remaining:)`: строку, которая
вышла бы за нижнюю границу содержимого текущего листа, «перепрыгиваем» на верх
содержимого следующего листа (`rect.origin.y = (page+1)*pageStride`). Серые
промежутки остаются пустыми; `DocxTextView.drawBackground` рисует там отдельные
белые листы A4 с тенью (число листов — из `usedRect`). **Выделение и форматирование
остаются нативными** (единый NSTextView) — в отличие от мульти-NSTextView.

Координаты: `textContainerInset.height = gap + topMargin`, поэтому container-Y=0 =
верх содержимого листа 0, а верх содержимого листа i = `i*pageStride`
(`pageStride = pageHeight + gap`; `pageContentHeight = pageHeight − top − bottom`).

**Разрыв страницы (req 3):** в `lineFragmentRect`, если символ перед `characterIndex`
== U+000C, строка переносится на следующий лист.

Проверено на экране: длинный текст авто-разбивается на листы A4 с промежутками/тенью;
двойной клик выделяет слово; Ж применяется (кнопка тулбара); разрыв страницы (Вставка →
Разрыв страницы) переносит текст на второй лист; обычный вид (переключатель в строке
состояния) — сплошной.

Ограничения v1: ⌘B на РУ-раскладке не срабатывает (общий баг буквенных шорткатов, не
пагинации — использовать кнопку тулбара/меню); горизонтальный/вертикальный колонтитулы,
номера страниц — не реализованы; при смене pageSettings пересчёт на следующем
updateNSView.

## Отклонённый подход (мульти-NSTextView) — историческая справка

## ⚠️ РЕЗУЛЬТАТ ИНКРЕМЕНТА 1 (важно для следующей попытки)

Пробовал подход «несколько NSTextView, делящих ОДИН NSLayoutManager+NSTextStorage»
(по контейнеру/вью на лист). Что выяснилось при проверке на экране:

- ✅ **Рендер и перетекание РАБОТАЮТ:** длинный текст авто-разбивается на листы A4 с
  промежутками/тенью; текст перетекает лист→лист. Ключ — **фиксированная высота
  контейнера** (`container.size.height = usableH` + `heightTracksTextView=false`;
  NSTextView сбрасывает это при инициализации, поэтому переустанавливать в relayout).
- ✅ **Разрыв страницы (req 3) РАБОТАЕТ:** `NSLayoutManagerDelegate.layoutManager(_:shouldUse:forControlCharacterAt:)`
  возвращает `.containerBreak` для U+000C → остаток переносится на следующий лист.
- ❌ **ВЫДЕЛЕНИЕ и ФОРМАТИРОВАНИЕ ЛОМАЮТСЯ (блокер):** при нескольких NSTextView на
  общем NSLayoutManager двойной клик выделяет **весь документ**, а не слово; Cmd+B не
  применяется. Регрессия задевает **даже первую страницу**. Причина —
  per-textview selection/word-granularity ломается, когда layout manager общий на
  несколько вью (каждый вью считает, что владеет всем текстом). Это НЕ чинится
  мелкой правкой; редактирование становится непригодным → откачено.

**Вывод:** «мульти-NSTextView + общий NSLayoutManager» НЕ годится как редактируемая
поверхность. Для следующей попытки рассматривать другие подходы:
1. **Один NSTextView, кастомная отрисовка листов** — NSTextView остаётся единой
   поверхностью редактирования (выделение/формат работают), а «листы A4 с промежутками»
   рисуются в `drawBackground`/оверлее с ВЕРТИКАЛЬНЫМИ ПРОБЕЛАМИ в раскладке на границах
   страниц (вставлять пустое пространство через layout manager на page-boundary). Разрыв
   страницы — тоже через вставку пробела до низа листа. Сложность: заставить один
   контейнер «пропускать» зоны промежутков (нестандартно для TextKit 1).
2. **TextKit 2** (`NSTextLayoutManager` умеет мультистраничность нативно) — но он
   авто-рендерит маркеры списков (ADR-027, из-за чего форсирован TextKit 1); нужно решить
   конфликт со списками иначе (напр. не через `textLists`, а полностью своими маркерами
   с подавлением системных).
3. **Редактируемый один-лист + отдельный непрерывный «предпросмотр печати»** с
   пагинацией (только просмотр, без правки) — компромисс.

Историческая справка ниже — исходный план (подход №, оказавшийся нежизнеспособным для
редактирования). Оставлен для контекста.

## Цель
В режиме «Вид страницы» — отдельные белые листы A4 на сером поле, с промежутками между листами и тенью, **текст перетекает** с одной страницы на следующую (как в MS Word / Pages), а не один непрерывный лист с пунктиром.

## Архитектурный подход (TextKit 1, мульти-контейнер)
Канонический путь пагинации TextKit 1:
- один `NSTextStorage` (общий),
- один `NSLayoutManager` — наш `DocxLayoutManager` (сохраняет отрисовку непечатаемых),
- **несколько `NSTextContainer`** — по одному на страницу, размер = usable area листа (`pageW - marginL - marginR` × `pageH - marginT - marginB`),
- **несколько `NSTextView`** — по одному на контейнер, все ссылаются на общий layoutManager/storage,
- контейнеры-страницы размещены в `PageCanvasView: NSView` (flipped) — это `documentView` скролла; между листами серые промежутки, под каждым — тень.

Текст автоматически перетекает: LM раскладывает глифы в контейнер 0 до заполнения, затем в контейнер 1, и т.д. Правка в любом `NSTextView` меняет общий storage → LM переразмечает все страницы.

## Точки интеграции (что затрагивается)
1. **`TextEditorRepresentable.makeNSView`/`updateNSView`** — вместо одного `DocxTextView` как documentView собираем `PageCanvasView` со страницами. Динамическое добавление/удаление страниц по мере роста/сжатия текста (`rebuildPages`).
2. **`DocumentController.textView`** — сейчас единственный. Должен указывать на страницу-с-фокусом (обновляется при `becomeFirstResponder`/начале редактирования). Форматирование/выделение работают по сфокусированной странице.
3. **`DocxLayoutManager`** (непечатаемые) — рисует по каждому контейнеру, менять не нужно (проверить позиционирование маркеров в multi-container).
4. **Зум** — `NSScrollView.magnification` масштабирует canvas целиком, ОК.
5. **Разрыв страницы `U+000C`** — форсирует перенос в следующий контейнер (`NSLayoutManager` уважает form feed? иначе — ручной хук в разбиении контейнеров).
6. **Синхронизация с моделью** — `textDidChange` любого page-view → `userDidEdit`. Один storage, так что как сейчас.
7. **Не-page режим** — один контейнер/textview во всю ширину (текущее поведение) — либо отдельный путь, либо canvas с 1 страницей без листа/промежутков.

## Известные сложности (риск регрессий)
- **Выделение между страницами** — каждый `NSTextView` имеет своё выделение; выделение через границу листа нетривиально (в v1 можно ограничить — выделение в пределах страницы).
- **Курсор/фокус** — переключение firstResponder между страницами; `controller.textView` следит за фокусом.
- **Позиционирование страниц при ресайзе/зуме** — пересчёт `PageCanvasView`.
- **Взаимодействие с текущими фичами** — списки/стили/непечатаемые правят storage напрямую через `controller.textView`; должны работать по сфокусированной странице.

## План инкрементов (каждый — сборка + проверка на экране, затем чекпоинт)
- **Инкремент 1 (рендер):** `PageCanvasView` + мульти-контейнер общего LM; длинный документ раскладывается на несколько листов A4 с промежутками/тенью; редактирование на сфокусированной странице. Проверка: набрать/вставить много текста → видно ≥2 листа, текст перетекает.
- **Инкремент 2 (фокус/контроллер):** `controller.textView` следит за фокусом; форматирование/списки/стили работают на любой странице.
- **Инкремент 3 (разрыв страницы):** `U+000C` переносит на новый лист; непечатаемый маркёр разрыва.
- **Инкремент 4 (полировка):** зум, ресайз-центровка, выделение в пределах страницы, не-page режим единый путь, синхр. pageSettings.
- **Инкремент 5:** печать проверить (NSPrintOperation уже пагинирует), round-trip не затронут.

## Откат
Если инкремент ломает редактор — режим page-view возвращается к текущему одиночному листу (v0.1.40), пока проблема не решена. Не-page режим не трогаем до инкремента 4.
