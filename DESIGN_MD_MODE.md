# DESIGN_MD_MODE.md — Режим Markdown в DocxEdit

> Статус: план. ADR-049 (черновик). Дата: 2026-07-30.
> База: v1.3.1. Цель: полноценный WYSIWYG-редактор MD внутри DocxEdit (Typora-style), без отдельного приложения.

## 1. Решение (ADR-049, черновик)

Одно приложение, два режима документа: **DOCX** (как сейчас) и **MD**.
Отдельное приложение отклонено: ~90% кода общее (multi-doc ADR-048, сессии, autorecover, updater, ribbon, экспорт, печать, тесты) — дублирование дало бы двойной бэклог и дрейф фич.

- Режим — свойство `DocumentSession.mode: .docx | .markdown` (per-window, естественно ложится на multi-doc).
- Определение режима: по расширению при открытии (`.md`/`.markdown` → MD); для нового документа — настройка + команда «Новый Markdown-документ».
- Модель (`DocumentModel`) **не меняется** — она надмножество обоих форматов. Ограничение — только на уровне инструментов UI.
- Редактирование — WYSIWYG на том же `NSTextView`/мосте. Source-режим с подсветкой синтаксиса — **не** в этом плане (отдельная задача, см. §5).

## 2. Матрица инструментов MD-режима

| Группа | MD |
|---|---|
| Стили абзаца: Обычный, Заголовок 1–6 | ✅ |
| Ж / К / Ч / `Код` (inline), блок кода | ✅ |
| Списки всех уровней и вариантов (ADR-026/028) | ✅ |
| Цитата (blockquote), горизонтальная линия (HR) | ✅ — **новые блоки модели, v1.4.2** |
| Ссылки (⌘K, auto-link), изображения, таблицы (GFM) | ✅ уже есть |
| Шрифт/размер/цвет/highlight/выравнивание/интервалы | ❌ скрыть |
| Поля, ориентация, колонтитулы, номера страниц, разрывы | ❌ скрыть |
| Вид страницы / пагинация / линейка | ❌ отключить (у MD нет страниц) |
| Зум, непечатаемые символы, статистика, поиск | ✅ |
| Сохранение | `.md` по умолчанию; DOCX/PDF/RTF/TXT/ODT — только через Экспорт |

## 3. План релизов

### v1.4.0 — MD Mode Core ✅ (2026-07-30, выпущен)
- `DocumentSession.mode`; определение по расширению в `loadFromURL` (точка: `DocxEditApp.swift:1111`, импорт MD уже есть).
- `saveDocument`/`saveDocumentAs` в MD-режиме: `allowedContentTypes = [.md]`, имя `Без имени.md` (точка: `DocxEditApp.swift:818-821`). DOCX и прочие — только через существующее меню Экспорт (`exportDocument(format:)`).
- Индикатор режима в статусбаре (рядом с языком/словами); клик — переключение режима с предупреждением при потере форматирования (DOCX→MD на непустом документе: «таблицы/стили/цвета будут упрощены», Сохранить копию / Отмена).
- Настройка «Формат новых документов: DOCX / Markdown» (Preferences → Основные) + ⇧⌘N «Новый Markdown-документ».
- Тесты: `DocxEditTests` — маппинг расширение→режим, дефолт сохранения.
- Ручная проверка: открыть `.md` → статусбар «Markdown» → ⌘S предлагает `.md`; открыть `.docx` → всё как раньше.

### v1.4.1 — Ribbon и меню в MD-режиме ✅ (2026-08-01, выпущен)
- Видимость групп ribbon по режиму — переиспользуем механизм ADR-043 (`RibbonGroupDef`/`isVisible`): в MD-режиме скрываем «Шрифт»-семейство/размер/цвет/highlight/выравнивание, вкладки «Разметка» целиком; «Таблица» остаётся (GFM-таблицы поддержаны).
- Меню «Формат»: те же пункты dimmed в MD-режиме (без удаления — через `.disabled`).
- Отключение `isPageView`/пагинации в MD-режиме (форс plain-вид, `applyPageViewStyle` no-op), скрыть переключатель вида из статусбара.
- Ручная проверка через computer-use: обе раскладки ribbon, dim-состояния меню.

### v1.4.2 — MarkdownIO: полный экспорт ✅ (2026-08-01, выпущен)
- Реализовано с **отступлением от первоначального плана**: новых Block-кейсов нет — quote/code/HR сделаны как абзацы со styleId «Quote»/«CodeBlock»/«HorizontalRule» + стандартные стили в `StandardParagraphStyle.all`. Бесплатно получили Codable/autorecover/DOCX round-trip (pStyle + styles.xml) и UI-вставку через пикер стилей.
- Импорт: ThematicBreak → HR, CodeBlock → абзацы по строкам, вложенные списки рекурсивно с level, ~~strikethrough~~, ссылки с URL, SoftBreak/LineBreak → \n.
- Экспорт: группировка CodeBlock-абзацев в один fence, списки без пустых строк, пустая строка между блоками, экранирование спецсимволов и лидирующих маркеров строки.
- HR в редакторе: пробел-носитель атрибута + линия в DocxLayoutManager.drawGlyphs.
- `MarkdownIO.exportMarkdown` (сейчас «минимальный», §7 CLAUDE.md): blockquote (`>`), fenced code blocks с языком, HR (`---`), экранирование спецсимволов (`* _ # [ ] \` |`), подстрочный/надстрочный → HTML-fallback `<sub>/<sup>`, highlight → `==text==` (GFM-ext, задокументировать).
- Импорт: blockquote/code fence/HR в модель — **новые блоки**: `QuoteBlock`, `CodeBlock(language:)`, `HorizontalRule` (DocxCore) + рендер в мосте (blockquote — отступ+курсив или боковая черта через paragraphStyle; HR — глиф-строка; code — моноширинный шрифт рана).
- DOCX round-trip новых блоков: blockquote → стиль «Quote», code → «HTML Code»/моноширинный стиль, HR → `<w:pBdr>` нижняя граница (как Word).
- Тесты: `MarkdownIOTests` — round-trip MD→model→MD для всех конструкций; `DocxRoundTripTests` — новые блоки через DOCX; `CodableRoundTripTests` — новые поля модели; `BridgeSnapshotTests` — рендер quote/code/HR.

## 4. Риски и митигации

1. **Тихая потеря форматирования при DOCX→MD** — жёсткое ограничение инструментов (v1.4.1) + предупреждение при переключении режима (v1.4.0). Митигация в плане с первого релиза.
2. **Round-trip MD неидемпотентен** (рендерер переписывает чужой MD по-своему) — приемлемо для WYSIWYG-редактора (как Typora); задокументировать; pretty-print опцией (v1.4.3).
3. **Новые блоки модели** (quote/code/HR) трогают DocxCore + мост + DOCX — самый рискованный релиз, поэтому выделен отдельно (v1.4.2) с полным покрытием тестами до мержа UI.
4. **Multi-doc**: два окна в разных режимах одновременно — Coordinator уже per-window (ADR-048), конфликтов не ожидается; проверить вручную в v1.4.1.

## 5. Осознанно не в плане

- Source-режим MD (подсветка синтаксиса + live preview) — отдельная большая задача (R12?), требует парсера в реальном времени и второй view-иерархии.
- Пользовательские markdown-диалекты (Obsidian [[wiki-links]], front-matter YAML) — front-matter сохранять как raw-блок — кандидат v1.5.x, по фидбеку.
- Совместное редактирование/iCloud — вне скоупа.
