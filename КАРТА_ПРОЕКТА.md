# КАРТА_ПРОЕКТА.md — карта проекта DocxEdit

Смысловая карта: как разложены модули, как проходят данные, где искать что.
Для плоского индекса файлов — см. [INDEX.md](./INDEX.md). Для истории
решений — [CLAUDE.md](./CLAUDE.md) §3 (ADR).

## Что это

Нативный macOS-редактор документов DOCX/DOC/RTF/TXT/Markdown/ODT.
Позиционируется как лёгкая приватная альтернатива MS Word. Swift 5.9,
SwiftUI + AppKit, minimum macOS 14 Sonoma, Universal (arm64 + x86_64).

## Слои и зависимости

```
┌─────────────────────────────────────────────────────────────┐
│                       DocxEdit (app)                        │
│  SwiftUI Views  ──▶  DocumentController  ──▶  движки       │
│         │                     │                             │
│         ▼                     ▼                             │
│   DocumentSession ◄──▶ NSDocumentBridge                     │
│                              │                              │
│         ┌────────────────────┼────────────────────┐         │
│         ▼                    ▼                    ▼         │
│  DocumentModel+ATT     DocxIO/MarkdownIO/RtfIO   PdfExporter│
│  (мост ↔ AppKit)             │                              │
└─────────────────────────────────────────────────────────────┘
                                │
                                ▼
                        DocumentModel (чистая, DocxCore)
                                │
                                ▼
                      EncodingDetector (для TXT)
```

- **DocxCore** не знает про AppKit. Он — источник истины по структуре документа.
- **DocxIO / MarkdownIO / RtfIO** — конвертеры файловых форматов ↔ DocxCore.
- **DocxEdit** склеивает всё, добавляет NSAttributedString-мост
  ([DocumentModel+AttributedString.swift](Sources/DocxEdit/Sources/DocumentModel+AttributedString.swift), ADR-010).

## Ключевые подсистемы

### 1. Мост модель ↔ UI (ADR-010)
`DocumentModel` — чистая структура. `NSTextView` работает с `NSAttributedString`.
Мост: `toAttributedString()` (модель → view) + `from(attributed:)` (view → модель,
поабзацный разбор, ADR-018). Custom NSAttributedString-ключи хранят метаданные
(styleId, charStyleId, listInfo, rowHeader, crossRef, comment-anchor) — они
переживают пересборку модели, поэтому это «канонический» способ связывать
сущности с текстом (см. §9 CLAUDE.md, конвенция «Идентичность фрагментов»).

### 2. NotificationCenter-шина (ADR-011)
Команды форматирования/вида ходят через `Notification.Name.docxEdit*`:
`AppDelegate` (пункт меню/шорткат) → пост → `Coordinator` окна (подписан)
→ метод `DocumentController`. С v1.3.0 (ADR-048) подписки Coordinator
фильтруются `isKeyWindow` — команда доходит только до активного окна.

### 3. Пагинация (ADR-037, подход №1)
`PaginatedTextContainer: NSTextContainer` переопределяет `lineFragmentRect(...)`
— строка за низом содержимого листа переносится на следующий лист. ОДИН
NSTextView, ОДИН layoutManager — нативное выделение/форматирование сохранены.
`DocxTextView.drawBackground(in:)` рисует листы A4 с тенью, серое поле,
колонтитулы, разрывы. Разрыв страницы: символ U+000C. Печать (⌘P) идёт своим
путём через `NSPrintOperation` (не через этот контейнер) — там настоящая
пагинация системы.

### 4. Ribbon (ADR-019, 6 вкладок ADR-043)
Свой `RibbonView` (не `NSToolbar`) с закладками Главная/Вставка/Разметка/
Таблица/Обзор/Вид + строка быстрого доступа. Настройка через каталог
`RibbonCustomization.swift` (23 группы + 24 команды с @MainActor-замыканиями).
Персист — `AppPreferences.hiddenRibbonGroups` + `ribbonFavorites`.

### 5. MD-режим (ADR-049)
Два подрежима: WYSIWYG (рендер модели, как DOCX) + source (сырой .md с
подсветкой, `MarkdownSourceView`). Переключение — `session.isMarkdownSourceMode`.
В WYSIWYG используется читаемая «лента» (v1.5.8/v1.6.8) — центрированная белая
колонка (600/720/900/full) на сером фоне, границы редактируемой области видны.
Смена режима MD↔DOCX сбрасывает масштаб к дефолту (ADR-053, v1.6.9).

### 6. Movement-компаньоны (DESIGN_R06.md §2)
Подсистемы R06+ — отдельные `final class`-движки, не в контроллере:
`CommentsEngine`, `TrackChangesEngine`, `UpdaterEngine`. Контроллер держит
ссылку и пробрасывает textView/session в `attach`. Это удерживает
`DocumentController` в разумном размере после распила ADR-035 (v1.6.5).

### 7. Multi-document (ADR-048, v1.3.0)
`WindowGroup(for: UUID.self)` — каждое окно = свой `DocumentSession`
(@StateObject в `DocumentWindowRoot`). `SessionAnchor` (NSViewRepresentable)
слушает `NSWindow.didBecomeMainNotification` и переключает
`AppDelegate.currentSession`. `AppDelegate.session` — computed getter.
`⌘N` фокусирует пустое окно или спавнит новое.

### 8. Auto-updater (ADR-041/045)
`UpdaterEngine` дёргает GitHub Releases API, сравнивает semver, показывает
`UpdateNotificationView` (баннер с markdown-notes). Установка — прогресс-бар
через `URLSessionDownloadDelegate` + detached bash-installer: ждёт выхода
родителя → монтирует .dmg → атомарный mv в /Applications → снятие quarantine
→ перезапуск. SHA256-верификация обязательна.

### 9. Command Palette (ADR-058, v1.8.0)
`CommandPaletteView` (⌘⇧P) — единая точка доступа к ~50 командам. Каталог —
`RibbonCommandDef.all` (тот же, что для «Избранного» ribbon, расширен в v1.8.0
до 50 команд: file ops, форматирование, панели, вид, вставки, инструменты).
`FuzzyMatcher.score` — subsequence + streak-бонус + early-match + substring.
Окно — `NSPanel(.nonactivatingPanel, .floating)` через `CommandPaletteWindow`
singleton. Клавиатура ↑↓ Enter Esc через `NSEvent.addLocalMonitor` по keyCode
(раскладко-независимо, ADR-027 п.4). Для команд, требующих `DocumentController`
напрямую (не через шину) — `DocumentSession.attachedController` (weak,
ставится в `DocumentController.attach`).

### 10. Selection Mini-Toolbar (ADR-057, v1.7.4)
Плавающая панель B/I/U/S/highlight/⌘K над выделением. Реализация: `NSPopover`
(`behavior=.applicationDefined`) в `Coordinator.updateSelectionMiniToolbar()` —
триггерится в `textViewDidChangeSelection`. Anchor rect: `layoutManager
.boundingRect(forGlyphRange:in:)` + `textView.textContainerOrigin`. Скрывается
при пустом выделении, `isReadingMode`, source-режиме, над inline-attachment.

### 11. Silent Autorecover (ADR-055, v1.7.0)
`~/Library/Application Support/DocxEdit/session.marker` создаётся в
`applicationDidFinishLaunching`, удаляется в `applicationWillTerminate`.
Если при следующем старте маркер существует — прошлый сеанс упал.
`AppDelegate.previousShutdownWasClean = !exists(marker)` (читается ДО перезаписи).
`presentAutorecoverIfNeeded` — если clean → тихо удалить оставшиеся `.json/.md`,
без диалога. `WindowCloseGuard` ветка «Не сохранять» → удаляет backup
конкретной сессии (multi-doc сценарий).

### 12. Focus Mode (ADR-059 п.4, v1.8.4)
Приглушение окружающих абзацев. Реализация — `NSLayoutManager.setTemporaryAttributes
(_:forCharacterRange:)`: все абзацы `tertiaryLabelColor`, текущий (по
caret paragraphRange) — `labelColor`. НЕ мутирует модель, отмена =
`removeTemporaryAttribute`. Хук в `refreshSelectionState` — обновление при
перемещении курсора.

### 13. MD режимы (ADR-049/059)
Три взаимоисключимых состояния для документа `mode == .markdown`:
- **WYSIWYG** (`!isMarkdownSourceMode && !isMarkdownSplitMode`) — рендер модели
  через мост, лента 720pt (ADR-054).
- **Source** (`isMarkdownSourceMode`) — `MarkdownSourceView` с подсветкой,
  `applyMarkdownSource` best-effort синкает модель (v1.6.0).
- **Split** (`isMarkdownSplitMode`, v1.8.3) — `HSplitView` source | WYSIWYG,
  live-обновление превью через доп. `attributedText = model.toAttributedString`
  в `applyMarkdownSource`.

## Потоки данных

### Открытие файла
```
Finder / ⌘O / drag-drop
    ↓
AppDelegate.loadFromURL(url)
    ↓
DocxIO / MarkdownIO / RtfIO — .import → DocumentModel
    ↓
DocumentSession.replace(with: model)   ← markSaved(url:)
    ↓
attributedText = model.toAttributedString(...)   [publishes]
    ↓
TextEditorRepresentable.updateNSView синкает textStorage
    ↓
applyPageViewStyle (авто-фит масштаба, ADR-053)
```

### Сохранение файла
```
⌘S / AppDelegate.saveDocument()
    ↓
DocumentModel.from(attributed: textView.textStorage)   [поабзацный разбор]
    ↓
DocxIO / MarkdownIO / RtfIO — .export → Data
    ↓
FileManager.write(to: url)   +   session.markSaved(url:)
```

### Форматирование (⌘B и т.п.)
```
Меню / кнопка ribbon
    ↓
AppDelegate постит Notification.Name.docxEditToggleBold
    ↓
Coordinator (key window!) → controller.toggleBold()
    ↓
NSTextView.shouldChangeText → textStorage.addAttribute → didChangeText
    ↓
undo-менеджер регистрирует шаг (ADR-017)
    ↓
notifyModelChange → session.markDirty
```

### Релиз
```
bash scripts/release.sh X.Y.Z "Codename" "" "changes"
    ↓
1. swift test (если Xcode) + smoke-тест бандла (всегда)
    ↓
2. build.sh → .app + .zip + .dmg + SHA256SUMS в build/vX.Y.Z/
    ↓
3. (опц.) notarize.sh
    ↓
4. update-changelog.sh — секция в CHANGELOG.md
    ↓
5. update-claude-md.sh — §4 «Текущий релиз» + строка в §5 таблице
    ↓
6. git commit + git tag vX.Y.Z
    ↓
7. publish-github.sh — gh release create + ротация (KEEP_RELEASES=6)
```

## Соглашения (кратко; полное — CLAUDE.md §9)

- Кнопки тулбара — только `.buttonStyle(.plain)` + явный `.frame()` (ADR-013)
- Диалоги — только `NSWindow(contentRect:)` + `NSHostingView(sizingOptions: [])` (ADR-039 п.7)
- Форматные правки — обёрнуты в `shouldChangeText` + `didChangeText` для undo (ADR-017)
- Идентичность фрагментов текста (закладки/комментарии/ревизии) —
  только через custom NSAttributedString-ключи
- Новые подсистемы — как final class-движки в своих файлах
- Notification-шина фильтрует `isKeyWindow` (ADR-048 multi-doc)
- Каждый релиз — на GitHub (`publish-github.sh` в `release.sh`)
- Дефолт AboutReleaseNotes.recent — 4 записи, обновляется вручную (проверка в release.sh шаг 0)
