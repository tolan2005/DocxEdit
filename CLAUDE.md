# CLAUDE.md — память проекта DocxEdit

\1. Сначала думай, потом кодируй

**Не додумывай. Не скрывай непонимание. Обозначай компромиссы.**

Перед реализацией:

- 	•	• Явно формулируй свои допущения. Если не уверен — спрашивай.
- 	•	• Если возможно несколько трактовок — представь их все, не выбирай молча.
- 	•	• Если есть более простой подход — скажи об этом. Возражай, когда это оправдано.
- 	•	• Если что-то неясно — остановись. Назови, что именно непонятно. Спроси.
- 	•	• Если есть вопросы - задавай по одному

\2. Простота прежде всего

**Минимум кода, решающего задачу. Ничего “на будущее”.**

- 	•	• Никаких функций сверх запрошенного.
- 	•	• Никаких абстракций ради кода, который используется один раз.
- 	•	• Никакой “гибкости” или “настраиваемости”, которую не просили.
- 	•	• Никакой обработки ошибок для невозможных сценариев.
- 	•	• Если написал 200 строк, а могло быть 50 — перепиши.

Спроси себя: “Сказал бы старший инженер, что это переусложнено?” Если да — упрощай.

\3. Точечные изменения

**Трогай только то, что необходимо. Убирай за собой, а не за других.**

При редактировании существующего кода:

- 	•	• Не “улучшай” соседний код, комментарии или форматирование.
- 	•	• Не рефактори то, что не сломано.
- 	•	• Придерживайся существующего стиля, даже если сделал бы иначе.
- 	•	• Если заметил посторонний мёртвый код — упомяни его, но не удаляй.

Если твои изменения создают “сирот”:

- 	•	• Убирай импорты/переменные/функции, которые стали неиспользуемыми ИЗ-ЗА твоих изменений.
- 	•	• Не удаляй ранее существовавший мёртвый код, если об этом не просили.

Проверка: каждая изменённая строка должна напрямую относиться к запросу пользователя.

\4. Выполнение, ориентированное на цель

**Определи критерии успеха. Повторяй, пока не подтвердишь результат.**

Превращай задачи в проверяемые цели:

- 	•	• “Добавь валидацию” → “Напиши тесты для некорректных входных данных, затем добейся их прохождения”
- 	•	• “Исправь баг” → “Напиши тест, воспроизводящий баг, затем добейся его прохождения”
- 	•	• “Отрефактори X” → “Убедись, что тесты проходят и до, и после”

Для многошаговых задач формулируй краткий план:

\1. \[Шаг\] → проверка: \[что проверить\]

\2. \[Шаг\] → проверка: \[что проверить\]

\3. \[Шаг\] → проверка: \[что проверить\]

Чёткие критерии успеха позволяют действовать самостоятельно. Расплывчатые критерии (“сделай, чтобы работало”) требуют постоянных уточнений.

## 1. Обзор

**DocxEdit** — нативное macOS-приложение для создания, редактирования и экспорта текстовых документов в форматах DOCX, DOC, RTF, TXT, Markdown, ODT. Позиционируется как лёгкая, бесплатная и приватная альтернатива MS Word.

Базовые принципы: нативность, скорость, приватность по умолчанию, совместимость с MS Word, привычный UX.

Подробная спецификация: см. [REQUIREMENTS.md](./REQUIREMENTS.md).

## 2. Технологический стек

- **Язык:** Swift 5.9+
- **UI:** SwiftUI (окна, инспекторы) + AppKit (текстовый движок, NSTextView, TextKit 2, NSMenu, NSToolbar)
- **Платформа:** macOS 14 Sonoma+
- **Архитектуры:** Universal (arm64 + x86\_64)
- **DOCX:** ZIPFoundation + Foundation XML
- **PDF:** PDFKit + Quartz
- **RTF:** Foundation NSAttributedString
- **Markdown:** swift-markdown (cmark)
- **Тесты (с v0.5.2, 184 теста, ~1.4 с):** XCTest, 5 таргетов — DocxCoreTests (модель/encoding/Codable/EncodingEdgeTests), DocxIOTests (DOCX round-trip, DocxFuzzTests, R06RoundTripTests, UnicodeEdgeTests, RealDocxCorpusTests с fixtures 21-24.docx), RtfIOTests, MarkdownIOTests, DocxEditTests (мост BridgeRoundTripTests, PropertyBasedRoundTripTests со SeededRNG, BridgeSnapshotTests через pointfreeco/swift-snapshot-testing). Snapshot-эталоны — в Tests/DocxEditTests/\_\_Snapshots\_\_/. Smoke-тест бандла — в build.sh.
- **CI:** *план* (GitHub Actions; пока не настроено, см. §7)

## 3. Архитектурные решения (ADR)

- **ADR-001** (2026-06-26): Выбор нативного стека Swift + SwiftUI/AppKit. Обоснование: лучший UX, производительность, размер дистрибутива.
- **ADR-002** (2026-06-26): Минимальная macOS 14 Sonoma. Обоснование: доступ к современным SwiftUI API, Observable, Inspector.
- **ADR-003** (2026-06-26): Freeware, прямое распространение через DMG. Не публикуется в Mac App Store.
- **ADR-004** (2026-06-26): DOCX — собственный импорт/экспорт через ZIPFoundation + XMLParser. Не используется LibreOffice/Cocoa-обёртки.
- **ADR-005** (2026-06-26): UI-раскладка — стандартные меню macOS + тулбары, а не Ribbon. Следуем Word для Mac, не Word для Windows.
- **ADR-006** (2026-06-26): Семантическое версионирование (semver). Внутренние коды релизов R01, R02, … мапятся на 0.MINOR.0.
- **ADR-007** (2026-06-26): Один язык в MVP (русский). Английский добавляется в R09.
- **ADR-008** (2026-06-26): Офлайн по умолчанию. Опциональные онлайн-фичи (проверка обновлений, расширенная проверка орфографии) — без телеметрии.
- **ADR-009** (2026-06-26): Сборка — Universal Binary единым DMG. Раздельные DMG для arm64 и x86\_64 публикуются параллельно.
- **ADR-010** (2026-06-28): NSAttributedString как единый мост DocumentModel ↔ NSTextView. Обоснование: WYSIWYG с минимальным кодом; NSTextView уже рендерит attributed string; DocumentModel хранит runs с CharacterAttributes, конвертируемые bidirectionally. selection-aware форматирование через NSTextStorage.
- **ADR-011** (2026-06-28): NotificationCenter для диспетчеризации команд форматирования из AppDelegate → Coordinator → DocumentController. Обоснование: развязка AppDelegate от lifecycle Coordinator, единственная точка Truth — NSTextView.textStorage.
- **ADR-012** (2026-06-28): Версионирование артефактов: build/v0.x.y/ — подпапки для каждого релиза. build/DocxEdit.app — текущий dev-бандл. Обоснование: сохранение истории, независимость релизов.
- **ADR-013** (2026-06-29): Кнопки тулбара через .buttonStyle(.plain) + явный .frame() внутри label. AlignButtonStyle/Toggle отклонены из-за непредсказуемого padding. NSColorWell (default style) вместо SwiftUI ColorPicker — компактный color swatch без артефактов рендера.
- **ADR-014** (2026-06-29): Зум через NSScrollView.magnification + allowsMagnification = true. Pinch-to-zoom синхронизируется с controller.zoomLevel через NSScrollView.didEndLiveMagnifyNotification. Шаги зума: 25/50/75/100/125/150/200/300/400%.
- **ADR-015** (2026-06-29): Вид страницы — упрощённый WYSIWYG: серый фон скроллвью + белый фон NSTextView + поля 72pt. Без собственного NSView-иерархии со страницами — планируется в R02.
- **ADR-016** (2026-06-30): Тулбар — нативный NSToolbar через SwiftUI .toolbar { ToolbarItemGroup/ToolbarItem } вместо кастомного HStack. Обоснование: кастомный HStack фиксированной ширины не управлял intrinsicContentSize вложенных AppKit-контролов (NSPopUpButton), из-за чего элементы наезжали друг на друга (v0.1.5–0.1.7 лечили симптом). NSToolbar даёт системную раскладку, авто-overflow в » и устраняет класс багов. Состояние кнопок биндится к DocumentController напрямую (без ручного Combine). Первопричина дополнительно закрыта setContentCompressionResistancePriority(.defaultLow) у пикера шрифта. **Отменяет ADR-013** для основного тулбара (паттерн .buttonStyle(.plain)+frame остаётся только в AlignmentPicker/FontSizeControl как вложенных виджетах).
- **ADR-017** (2026-06-30): Undo форматирования через NSTextView.shouldChangeText(in:replacementString:) + didChangeText(). Обоснование: форматные методы DocumentController правят textStorage напрямую (beginEditing/addAttribute/setAttributes/endEditing), минуя пайплайн ввода NSTextView, поэтому undo-менеджер не регистрировал атрибутные правки и Cmd+Z их не откатывал, а DocumentModel рассинхронизировался. Решение: оборачивать каждую правку диапазона в shouldChangeText(in:replacementString: nil) (до редактирования) и didChangeText() (после) — стандартный паттерн регистрации undo для attribute-only изменений NSTextView. replacementString: nil сигнализирует «меняются только атрибуты, не текст». Для applyAlignment диапазон undo — объединение (NSUnionRange) всех затронутых абзацев. applyToRange сохраняет собственный begin/endEditing; двойной endEditing не вводится (фикс v0.1.9). Баланс счётчика редактирования сохранён.
- **ADR-018** (2026-06-30): Атрибуты абзаца (R02) — двунаправленный мост ParagraphAttributes ↔ NSParagraphStyle. makeNSParagraphStyle() уже строил стиль (модель→вид); добавлена обратная ParagraphAttributes.from(nsParagraphStyle:), а DocumentModel.from(attributed:) переписан на **поабзацный разбор** (NSString.paragraphRange) с извлечением стиля каждого абзаца. Обоснование: прежняя реализация на каждом редактировании ставила абзацам ParagraphAttributes() по умолчанию, теряя выравнивание/отступы/интервалы при сохранении в модель. Правки абзаца (выравнивание, межстрочный интервал, отступы) идут через общий хелпер mutateSelectedParagraphs с регистрацией undo (ADR-017); applyAlignment переведён на него. Поабзацный разбор поведенчески эквивалентен старому по runs (выверено на ""/"\\n"/"a\\n"/"a\\nb").
- **ADR-019** (2026-06-30): Тулбар — **ribbon с закладками** (Главная/Разметка/Вид) в стиле MS Word for Mac, кастомный SwiftUI-вид RibbonView (не NSToolbar). Обоснование: пользователь запросил закладки + многострочную раскладку, где элементы не скрываются; нативный NSToolbar принципиально однострочный и прячет лишнее в overflow », поэтому под это требование он не подходит. Ribbon — отдельная панель в контенте окна (под системным заголовком): tab-bar + группы; «Главная» в 2 строки (Шрифт, Абзац), «Разметка» (вид страницы; задел под поля/ориентацию), «Вид» (масштаб). Раскладка детерминированная (фиксированные frames, ADR-013-паттерн кнопок). **Отменяет ADR-016** (NSToolbar) и **ADR-005** (в части «не Ribbon» — современный Word for Mac как раз ribbon). Состояние биндится к DocumentController напрямую. Виджеты FontPickerView/FontSizeControl/AlignmentPicker/ColorWellView переиспользованы.
- **ADR-020** (2026-06-30): Состояние документа (имя в заголовке, \*-признак изменения, подтверждение при закрытии). Заголовок — .navigationTitle(session.windowTitle) (имя файла +  \* при isDirty). Подтверждение закрытия — WindowCloseGuard (NSViewRepresentable), который ставит себя делегатом NSWindow и реализует windowShouldClose с диалогом Сохранить/Не сохранять/Отмена; «Сохранить» зовёт AppDelegate.saveDocument() и закрывает только если isDirty сбросился (иначе панель сохранения отменили). Чтобы не сломать делегата SwiftUI — **форвардинг** через responds(to:)/forwardingTarget(for:) на предыдущего делегата. Реактивность: NSDocumentBridge это final class, мутация полей не триггерит @Published bridge, поэтому сохранение идёт через DocumentSession.markSaved(url:) с явным objectWillChange.send(). Доступ к MainActor-состоянию из nonisolated методов представления — через MainActor.assumeIsolated (всё на главном потоке). Также синхронизируются нативные isDocumentEdited (точка в кнопке закрытия) и representedURL (proxy-иконка).
- **ADR-021** (2026-06-30): Дублирование пунктов меню на ribbon «как в MS Word» (правило: нет кнопки на тулбаре Word → нет и у нас). Добавлены: строка быстрого доступа над закладками (Создать/Открыть/Сохранить/Отменить/Вернуть) и на «Главной» группы «Буфер обмена» (Вырезать/Копировать/Вставить) и «Редактирование» (Найти/Заменить). Файл/Undo → AppDelegate/controller.undo()-redo() (через textView.undoManager). Буфер обмена → цепочка респондеров NSApp.sendAction(#selector(NSText.cut/copy/paste)) (доходит до первого респондера — NSTextView). Поиск → NSTextView.performTextFinderAction с тегом NSTextFinder.Action (find=showFindInterface, replace=showReplaceInterface); меню Найти/Заменить тоже подключены к контроллеру. **Без кнопок** (в Word их на тулбаре нет): Сохранить как, Экспорт (PDF/DOCX/MD/RTF), Недавние, О программе.
- **ADR-022** (2026-06-30): Открытие файла из Finder («Открыть в приложении») — три фикса. (1) Удалён NSDocumentClass: NSDocument из всех CFBundleDocumentTypes в build.sh: macOS видел этот ключ и роутил открытие через NSDocumentController вместо application(\_:open:), запрос тихо терялся. (2) Буферизация pendingOpenURL для гонки инициализации: application(\_:open:) может вызваться раньше привязки session в .onAppear; session.didSet догружает отложенный URL. (3) **DMG HFS+ + SetFile -a v:** переход с APFS на HFS+ позволил стилизовать Finder-окно через AppleScript (позиции иконок); AppleScript при открытии DMG выставлял kIsInvisible (0x4000) в FinderInfo на DocxEdit.app — Finder прятал приложение. Фикс: после AppleScript добавлен SetFile -a v для снятия флага невидимости. **Диагностика:** флаг обнаружен через xattr -px com.apple.FinderInfo (байт 8 = 0x60 вместо 0x20); после SetFile -a v = 0x20 (только kHasBundle). **Затрагивает:** build.sh (plist, DMG, SetFile) и DocxEditApp.swift (session/pendingOpenURL). Первопричина: AppDelegate.session присваивается в .onAppear окна SwiftUI, а Finder вызывает application(\_:open:) → loadFromURL зачастую **раньше** появления окна; session?.replace(...) через optional-chaining молча выполнялся как no-op, файл импортировался «в пустоту» и визуально не открывался. Решение: если session == nil, loadFromURL сохраняет URL в pendingOpenURL и выходит; session получил didSet, который при привязке догружает отложенный URL. Делает открытие независимым от порядка событий «delegate open vs window onAppear». Затрагивает только DocxEditApp.swift; модель/мост/тулбар не трогает.
- **ADR-023** (2026-06-30): Настройки страницы и печать (v0.1.20). (1) **Preferences «Страница»**: AppPreferences.defaultPageSettings: PageSettings (JSON в UserDefaults), вкладка «Страница» в PreferencesView — пикер формата (A3/A4/A5/Letter/Legal), ориентация (Книжная/Альбомная), пресеты полей (Стандартные/Узкие/Широкие) + ручной ввод в см; newDocument() использует AppPreferences.shared.defaultPageSettings. (2) **WYSIWYG с реальными полями**: applyPageViewStyle читает session.bridge.model.pageSettings.margins и передаёт их в textContainerInset вместо фиксированных 72/60pt. (3) **Печать** (docxEditPrint): AppDelegate.printDocument() постит Notification.Name.docxEditPrint; Coordinator.onPrint() создаёт NSPrintInfo из controller.session?.bridge.model.pageSettings и запускает NSPrintOperation(view: textView, printInfo: pi).run() — системный диалог печати; ⌘P в меню и кнопка «Принтер» в строке быстрого доступа ribbon. (4) **RTF-экспорт** (фикс ошибки 66062): добавлен .documentType: NSAttributedString.DocumentType.rtf в attrs RtfIO.exportRTF — без него NSAttributedString сериализует как plain text и падает с NSFileWriteInapplicableStringEncodingError на не-ASCII. (5) **MD-экспорт**: renderTable переписан — заголовок из реальных ячеек, правильный разделитель ---, закрывающий |, экранирование | в содержимом; renderMarkdown разделяет пробелы и контент перед wrap в \*\*/\*.
- **ADR-024** (2026-07-01): Шрифты и приложение по умолчанию (v0.1.21). (1) **Fallback на избранный шрифт**: CharacterAttributes.nsAttributes(defaultFont:fallbackFontName:) — если fontName рана указан, но NSFont(name:) не резолвится (шрифта нет в системе), подставляется первый шрифт из AppPreferences.shared.favoriteFonts вместо системного defaultFont; параметр прокинут через DocumentModel.toAttributedString(fallbackFontName:) из обоих вызовов в DocumentSession.replace(with:)/reset(). Известное ограничение: подстановка только на уровне отображения — DocumentModel.from(attributed:) перечитывает .font.familyName из живого textStorage при любой правке, поэтому имя избранного шрифта может «запечься» в модель вместо оригинального при сохранении после редактирования; не исправлено (отдельная архитектурная задача). (2) **Независимая замена шрифта/размера** (фикс бага, визуально подтверждено): applyFont/applyFontSize в DocumentController раньше строили один общий NSFont через currentFont() и применяли его целиком на диапазон через applyToRange(font:range:) — из-за этого смена семейства шрифта на выделении с разными размерами/начертаниями стирала эти различия. Заменено на NSFontManager.shared.convert(\_:toFamily:)/convert(\_:toSize:), применяемые **по каждому под-рану отдельно** (applyFontFamily/applyPointSize, enumerateAttribute(.font, in: range)). (3) **Диалог замены шрифтов** (визуально подтверждено): FontReplaceView.swift — таблица шрифтов документа (DocumentController.fontsUsedInDocument()), отмечает отсутствующие в системе, Picker замены на строку (секции Избранные/Недавние/Все — см. ниже), кнопка «Заменить шрифты» → DocumentController.replaceFont(from:to:). Открывается через меню Формат → «Заменить шрифты…» → docxEditShowFontReplace → Coordinator.onShowFontReplace(), создающий NSWindow с явным contentRect+NSHostingView (не NSHostingController/NSWindow(contentViewController:) — тот вариант не показывал окно из-за нулевого intrinsic size до первого layout-прохода SwiftUI). (4) **Changelog в «О программе»** (визуально подтверждено): NSApp.orderFrontStandardAboutPanel(options: \[.credits: NSAttributedString\]) — AboutReleaseNotes.recent (статический массив последних 3 релизов, обновляется вручную при каждом релизе синхронно с §5; текущий релиз всегда добавляется первым). (5) **«Сделать приложение по умолчанию»** (визуально подтверждено пользователем): DefaultAppsView.swift — вкладка в Preferences, FileTypeAssociation.all зеркалит 5 UTI из CFBundleDocumentTypes; NSWorkspace.shared.urlForApplication(toOpen:)/setDefaultApplication(at:toOpen:completionHandler:); единая кнопка «Изменить на другое приложение…» покрывает и «стать умолчанием», и «отказаться в пользу другого приложения» (на macOS нет состояния «без умолчания»). Автотест через computer-use не смог подтвердить клик по кнопке назначения (вероятно, проблема автоматизации, не кода) — работоспособность подтверждена ручной проверкой пользователя.

(6) «Правка» — «Найти/Заменить/Расширенный поиск/Перейти к» в подменю «Найти». (7) «Инструменты» — только статистика документа + отчёт об открытии. **Что НЕ тронуто**: все appDelegate.\* методы (только их места вызова из меню), все шорткаты (⌘B/I/U, ⌘⌥1..6, ⌘F, ⌘K, ⌘⌥T, ⌘⇧E, ⌘M и т.д. — мышечная память сохранена), ribbon, контекстные меню. Единственный побочный эффект — «Комментарий» под старым ⌥⌘M теперь в «Обзор → Комментарии → Вставить комментарий», а не на верхнем уровне «Вставка»; шорткат работает.
- **ADR-040** (2026-07-16, v1.1.0): Публикация релизов на GitHub. scripts/publish-github.sh — обёртка над gh CLI. Создаёт GitHub Release с тегом vX.Y.Z, аплоадит DocxEdit-X.Y.Z.dmg + DocxEdit-X.Y.Z.app.zip + SHA256SUMS. Тело релиза извлекается из соответствующей секции CHANGELOG.md через awk (шаблон ## \[X.Y.Z\] / ## vX.Y.Z). Идемпотентно: если релиз с этим тегом уже есть — gh release upload --clobber + gh release edit (обновление title/notes); повторный запуск не создаёт дубль (позволяет перевыпустить артефакт без bump версии). Pre-release суффиксы (-rc.N/-beta.N/-alpha.N) → флаг --prerelease. **Ротация**: после успешной публикации gh release list --limit 100 --json tagName,isDraft,createdAt → сортировка по created desc, всё за пределами топ-KEEP\_RELEASES (env, default 3, диапазон 1-20) удаляется через gh release delete --yes **без** --cleanup-tag (git-теги сохраняются как исторический архив). Draft-релизы игнорируются в подсчёте. Pre-release учитываются наравне со stable (осознанное упрощение v1). Ошибка публикации не откатывает локальные артефакты и не откатывает CHANGELOG/CLAUDE.md — печатается инструкция «повторить вручную». Флаг release.sh --no-publish пропускает шаг; отсутствие gh / GitHub remote / git-репо — graceful skip с warning, не падение. Инструмент — gh CLI (brew install gh + gh auth login), выбран вместо curl+PAT (не нужно хранить токен клиенту) и вместо GitHub Actions (не хотим CI-раннера для локальных сборок). release.sh этап 7 автоматически вызывает publish-github.sh.
- **ADR-041** (2026-07-16, v1.1.0): Встроенный auto-updater. Реализация без Sparkle-зависимости — своя минимальная схема. **UpdaterEngine.swift**: URLSession.data(for:) дёргает https://api.github.com/repos/tolan2005/DocxEdit/releases/latest, парсит JSON в GitHubRelease (Decodable). Компаратор Semver.compare(a, b) разбирает vX.Y.Z → \[Int\] (pre-release суффиксы -rc.N игнорируются — v1-ограничение, задокументировано); если удалённая > текущей CFBundleShortVersionString — @Published var availableUpdate заполняется, AppDelegate по Timer раз в 5 сек проверяет и показывает **UpdateNotificationView** (banner-окно с release notes из body, кнопками Install/Later/Skip). Скачивание: URLSession.download(for:) .dmg (fallback .app.zip) в FileManager.temporaryDirectory; **обязательная** SHA256-верификация против SHA256SUMS из того же релиза (парсер SHA256Verifier.expectedHash + shasum -a 256 для реального хеша) — при несовпадении файл удаляется, обновление отменяется с ошибкой ("Не удалось проверить целостность файла"). Успех → NSWorkspace.shared.open(dmg); пользователь перетаскивает вручную в /Applications (in-place replace через helper-скрипт — задел v1.2.x, см. REQUIREMENTS\_AUTOUPDATE §4.5). **Настройка периодичности** (UpdateCheckFrequency, AppPreferences): .onLaunch/.daily/.weekly/.never; UI на вкладке «Основные» Preferences (Picker). При .never — 0 сетевых запросов (проверка interval == nil в checkOnLaunchIfNeeded). Ручная проверка — меню «DocxEdit → Проверить обновления…» (checkNow — игнорирует skippedVersion, показывает NSAlert если нет обновлений). **Skip-версия**: AppPreferences.skippedUpdateVersion — пропущенная версия не предлагается снова, пока не выйдет более новая. **Приватность (ADR-008)**: User-Agent строго DocxEdit/<v> (macOS) без ID/UUID/hostname; запросы идут напрямую к api.github.com и github.com, никаких промежуточных сервисов; никаких cookies/tokens. UI-паттерн — NSWindow(contentRect:) + NSHostingView(sizingOptions:\[\]) (обязательно, ADR-039 п.7 — единственный разрешённый после краха «Свойств таблицы»). Автоматическая проверка через 2 сек после applicationDidFinishLaunching (не блокирует splash). **Не сделано в v1.1.0** (осознанно, задачи v1.2.x): прогресс-бар при загрузке (сейчас 0→1 по факту завершения), in-place replace для .app.zip через detached helper-скрипт (см. REQUIREMENTS §4.5), кеш metadata на 1 час против rate-limit кластерного NAT (REQUIREMENTS §8 R2), snapshot-тест UpdateNotificationView. **Тесты**: UpdaterTests.swift — Semver (10 кейсов: equal/newer/older/pre-release/short-forms/normalize), SHA256Verifier (парсинг SHA256SUMS: 4 кейса), UpdateCheckFrequency (интервалы). Сетевые/UI-тесты через ручную проверку. **Известное ограничение**: до нотаризации (Developer ID + Apple notary) все скачанные .dmg дают Gatekeeper-варнинг при первом запуске — правый клик → Открыть; это R1 в REQUIREMENTS\_AUTOUPDATE §8, закрывается post-1.1.
- **ADR-038** (2026-07-06): Колонтитулы и номера страниц (v0.1.46), **визуально верифицировано через computer-use**. Модель: DocumentModel.headerFooter: HeaderFooter (текст верхнего/нижнего + выравнивание; плейсхолдеры {page}/{pages}/{date}), сохраняется через applyAttributed/NSDocumentBridge.setHeaderFooter. UI: Вставка → «Номера страниц» (быстрый footer {page} по центру) + «Колонтитулы…» (диалог HeaderFooterView — 2 поля + сегм. выравнивание); шина docxEditTogglePageNumbers/docxEditShowHeaderFooter. **DOCX round-trip:** экспорт пишет word/header1.xml/footer1.xml + Content\_Types Override + document.xml.rels Relationship (rIdHdr1/rIdFtr1) + <w:sectPr> (headerReference/footerReference + pgSz/pgMar); {page}→<w:fldSimple w:instr=" PAGE ">, {pages}→NUMPAGES, {date}→DATE; импорт — HeaderFooterPartParser. ## 7. Известные ограничения и технический долг

- **Тестирование при релизе:** release.sh перед сборкой проверяет, что AboutReleaseNotes.recent содержит запись выпускаемой версии (шаг 0, добавлен в v0.1.24 — ручное обновление About забывалось в 0.1.22 и 0.1.23, оба раза баг дошёл до пользователя); гоняет swift test — **работает локально с 2026-07-13** после установки пользователем полного Xcode и sudo xcode-select -s /Applications/Xcode.app/.... Всего 36 тестов (12 DocxCoreTests + 4 DocxIOTests + 20 DocxRoundTripTests), проходят за ~90 мс. **Первый же прогон XCTest нашёл 2 бага**, невидимых 5 месяцев: (а) Archive.Entry — internal у ZIPFoundation, DocxIOTests.swift не компилировался (заменено на bool hasEntry); (б) **критический баг EncodingDetector с v0.1.0**: CP1251-кириллица определялась как UTF-16LE — эвристика ≥0x20 в decodeAsUtf16WithoutBOM ловила любую 8-битку. Тест testEncodingDetector\_Windows1251 существовал с v0.1.0, никогда не запускался. Фикс: переставить порядок в EncodingDetector.detect — сначала кириллические 8-битные (isCyrillic, доля кириллицы >30%), потом UTF-16 без BOM как fallback. build.sh всегда выполняет **smoke-тест бандла** (структура .app, валидность Info.plist через plutil, Mach-O/арх через lipo, соответствие версии; codesign — мягкая проверка).
- **CI не активирован:** GitHub Actions конфиг существует, но пока тесты не запускаются автоматически на каждый коммит. Snapshot-тесты — реализованы (v0.5.2, BridgeSnapshotTests, эталоны в репо, precision 0.98). Property-based — реализованы (v0.5.2, PropertyBasedRoundTripTests, seedable SeededRNG).
- **DOCX round-trip:** поддерживаются базовые OOXML-элементы; таблицы, изображения, гиперссылки, сноски — в R03.
- **RTF round-trip:** ограничен возможностями NSAttributedString.
- **Markdown round-trip:** импорт полный (swift-markdown), экспорт минимальный.
- **Вид страницы (упрощённый):** поля теперь реальные из pageSettings (v0.1.20). Нет фиксированной ширины страницы и разбивки на страницы — текст адаптируется к ширине окна. True page-view (фиксированная ширина A4 + пагинация) — в R02.
- **Атрибуты параграфов в UI:** интервал/отступы/выравнивание подключены к NSTextView через NSParagraphStyle и сохраняются в модель (v0.1.12, ADR-018). Остаётся: hangingIndent, listInfo (списки), точные значения отступов/интервала через диалог — R02.
- **Round-trip абзаца не покрыт тестами:** from(attributed:) переписан и выверен рассуждением на краевых случаях, но юнит-тестов нет (мост в UI-таргете DocxEdit, без тест-таргета; XCTest локально недоступен). Проверка — ручным запуском .app.
- **Undo/Redo (форматирование) — закрыто в v0.1.10 (ADR-017):** форматные методы оборачивают правки в shouldChangeText(in:replacementString:) + didChangeText(), NSTextView регистрирует undo для B/I/U/S/цвета/шрифта/размера/выравнивания, Cmd+Z откатывает. Остаётся: визуальная проверка отката требует ручного запуска .app (UI-/snapshot-тестов нет); единый undo-менеджер модели и согласованный redo атрибутов — план R02.
- **Тулбар — визуальная верификация:** миграция на NSToolbar (v0.1.9) собрана и smoke-тестирована, но отрисовка проверяется только запуском .app (юнит/snapshot-тестов на UI нет).
- **Нотаризация:** сборка подписана ad-hoc. Для публичного распространения нужен Apple Developer ID + нотаризация.
- **Зум pinch:** didEndLiveMagnifyNotification обновляет label только после завершения жеста, не в реальном времени.
- ✅ **РЕШЕНО в v0.1.91: краш «Свойств таблицы»** (открыт с v0.1.70, 4 неуспешные попытки — v0.1.71/74/75/76). Корень (из полного crash-лога v0.1.90): NSWindow(contentViewController: NSHostingController(...)) включал NSHostingView.updateAnimatedWindowSize из windowDidLayout — авторесайз окна внутри display-цикла кидал NSException «attempting to update layout during layout» → abort(). Все остальные диалоги DocxEdit используют паттерн NSWindow(contentRect:) + NSHostingView и никогда не падали. Фикс — унификация на этот же паттерн с hosting.sizingOptions = \[\]; условные секции внутри диалога заменены на постоянно видимые .disabled + .opacity(0.4) для фиксированной высоты. См. ADR-039 п.7 и память table\_properties\_crash.md. **Правило для будущих диалогов:** только NSWindow(contentRect:) + NSHostingView(sizingOptions: \[\]).

    - Новая кодировка → EncodingEdgeTests.
    - Известное ограничение с планом починки → тест с throw XCTSkip("причина — задача RXX") вместо XFail.
  - **Snapshot-эталоны** (Tests/DocxEditTests/\_\_Snapshots\_\_/\*.png) — коммитятся вместе с кодом. При изменении рендера тест падает с diff-картинкой. Для перезаписи — раскомментировать isRecording = true в setUp() затронутого файла, прогнать, вернуть false, закоммитить обновлённые PNG.
  - **Fixtures реальных docx** (Tests/DocxIOTests/Fixtures/\*.docx) — 4 файла от пользователя, покрывают TOC, VML, SmartArt, сложные поля. Не удалять при рефакторингах.
  - **Property-based** (PropertyBasedRoundTripTests) — seedable PRNG (SeededRNG), запускает 30-50 итераций. При падении: seed в SeededRNG(state:) и iter-index в сообщении дают воспроизводимость.
  - **Диагностический отчёт**: testImportReportsForCorpus печатает ImportReport.entries для каждого файла корпуса — быстрый way to see какие OOXML-элементы ещё не поддержаны.
  - **Локальный запуск**: swift test (нужен полный Xcode, не Command Line Tools); гейтом релиза управляет scripts/release.sh шаг 1.
- **Пирамида проверок (что когда гоняем):**
  - **Каждый коммит (dev-цикл):** swift build (компиляция), при заметной правке — swift test целиком (~1.4 с) или конкретный --filter FooTests.
  - **Каждый релиз (patch,** **0.x.Y****):** swift test целиком (полный сьют, гейт в release.sh шаг 1) + smoke-тест бандла (build.sh) + AboutReleaseNotes.recent содержит запись. Красный тест = релиза нет.
  - **Каждый milestone (minor,** **0.X.0** **= закрытие Rxx):** всё из релиза + **ручное открытие** Tests/DocxIOTests/Fixtures/21-24.docx в собранном .app (визуальная проверка ImportReport и отсутствия визуальных багов) + прогон snapshot-тестов с обязательным глазным осмотром обновлённых PNG (эталоны могут «съезжать» между версиями AppKit) + актуализация §6 CLAUDE.md (✅ реализовано / 🚧 недобитки / 📋 план).
  - **Что** ***не*** **гейтится автоматически, но обязано быть проверено вручную перед minor**: реальный сохранённый DOCX открывается в MS Word без ошибок; печать (⌘P) даёт корректный PDF; XCUITest (планируется) — пока замещается ручным walkthrough основных операций.
