# Требования к приложению-редактору документов для macOS

> **Рабочее название:** `DocxEdit` (далее по тексту — **Приложение**)
> **Дата документа:** 2026-06-26
> **Версия документа:** 1.0
> **Статус:** Черновик, согласован базовый набор решений

---

## 1. Резюме проекта

Нативное macOS-приложение для создания, редактирования и экспорта текстовых документов в распространённых форматах (`docx`, `doc`, `rtf`, `txt`, `md`, `odt`). Основной внутренний формат — **OOXML/DOCX**. Приложение позиционируется как **лёгкая, бесплатная и приватная** альтернатива MS Word для повседневной работы.

### 1.1. Ключевые принципы

- **Нативность.** Swift + SwiftUI + AppKit, без Electron и сторонних рантаймов.
- **Скорость запуска.** Холодный старт ≤ 1.5 с на референсной машине (M1, 16 ГБ RAM).
- **Приватность по умолчанию.** Без телеметрии, без облака, документы не покидают машину.
- **Совместимость.** Без потерь открывает/сохраняет `docx` из MS Word 2007+ и LibreOffice.
- **UX приближен к Word.** Стандартная раскладка меню macOS + тулбары в духе Ribbon, знакомые пользователю Word сочетания клавиш.

### 1.2. Целевые платформы

| Параметр | Значение |
|---|---|
| Минимальная ОС | macOS 14 Sonoma (Darwin 23) |
| Архитектуры | Universal: arm64 + x86_64 |
| Локализация MVP | ru-RU (русский) |
| Распространение | Прямая загрузка DMG с сайта + GitHub Releases |
| Магазин | Не публикуется в Mac App Store (freeware, прямое распространение) |

### 2.2. Сторонние Swift Package зависимости (минимальный набор)

- `zipfoundation/ZIPFoundation` — работа с DOCX как с ZIP
- `swiftlang/swift-markdown` — Markdown
- `pointfreeco/swift-snapshot-testing` — snapshot-тесты UI
- `swiftlang/swift-collections` — `OrderedDictionary`, `Deque` (по необходимости)

> Решение о добавлении каждой новой зависимости принимается с учётом: лицензия (предпочтительно MIT/Apache-2.0), поддержка, размер, стабильность.

### 2.3. Архитектурный каркас

- **MVVM + Coordinator** на уровне приложения (окна, документы, lifecycle).
- **Document Model** — отдельный слой, не зависящий от UI (модель OOXML-документа, маппинг в `NSAttributedString` для рендеринга).
- **Command/Action pattern** — каждое действие пользователя (форматирование, вставка, экспорт) — отдельная команда с `do`/`undo`/`redo`.
- **Sandbox-friendly.** Приложение запускается в App Sandbox, доступ к файлам — через `NSOpenPanel`/`NSSavePanel` или `security-scoped bookmarks`.

## 3. Целевая аудитория и сценарии использования

### 3.1. Сегменты аудитории

1. **Домашние пользователи и студенты** — написание рефератов, курсовых, писем, заметок. Важно: простота, проверка орфографии, шаблоны.

### 4.3. Совместимость с DOCX

Приложение гарантирует совместимость с документами, созданными в:

- Microsoft Word 2007, 2010, 2013, 2016, 2019, 2021, 2024, 365
- LibreOffice Writer 7.x+
- Apple Pages (с ограничениями)
- Google Docs (экспорт в DOCX)

Измеряемые критерии:

- 100% тестовых документов (corpus из 200+ `.docx`) открываются без ошибок.
- Сохранённый документ открывается в MS Word без запроса на восстановление.
- Сохранённый документ проходит валидацию Office Open XML schema validator.

### 5.4. Панели инструментов (Toolbar)

Предоставляется **набор тулбаров**, имитирующих логические группы из Ribbon Word:

1. **«Главная»** — Шрифт (B/I/U, размер, цвет), Абзац (выравнивание, списки, отступ), Формат по образцу.

- Показывать/скрывать панели через меню «Вид → Панели инструментов».

## 7. План релизов

### 7.1. Стратегия версионирования

Используется **семантическое версионирование** (semver) `MAJOR.MINOR.PATCH`:

- **MAJOR** (1, 2, …) — крупные релизы, маркетинговые поводы, могут содержать несовместимые изменения.
- **MINOR** (0.1, 0.2, …) — функциональные релизы, обратно совместимые в рамках серии.
- **PATCH** (0.1.1, …) — баг-фиксы и мелкие улучшения.

До выхода v1.0.0 приложение находится в статусе **Pre-release / Early Access**. Каждый релиз публикуется как `0.x.0` (с патчами при необходимости). Версия v1.0.0 — первый «публичный стабильный» релиз.

Параллельно ведётся **внутренний номер релиза** вида `R<NN>` (R01, R02, …) для удобства планирования, маппинг 1:1 на `0.MINOR.0`.

## 8. Процедуры выпуска релиза (Release Workflow)

### 8.1. Подготовка релиза

1. **Создать ветку релиза.**
   ```bash
   git checkout develop
   git pull
   git checkout -b release/0.3.0
   ```
2. **Заморозить фичи** — закрыть merge-ветки `feature/*` (кроме критических баг-фиксов).
3. **Обновить версию:**
   - `MARKETING_VERSION = 0.3.0` в `project.pbxproj` / `Info.plist`.
   - `CURRENT_PROJECT_VERSION = <build_number>` (монотонно растёт).
   - `CFBundleVersion` синхронизируется.
4. **Обновить `CHANGELOG.md`** с перечнем изменений.
5. **Обновить `CLAUDE.md`** (см. п. 9).
6. **Запустить полный регресс-тест** (`make test` или аналог).
7. **Прогнать ручное smoke-тестирование** по чек-листу MVP/текущего релиза.
8. **Собрать Release-кандидаты (RC1, RC2, …)** и распространить внутри.

### 8.2. Сборка артефактов

**Сборка Universal Binary и DMG (через `xcodebuild` + скрипт):**

```bash
# Переменные
APP_NAME="DocxEdit"
VERSION="0.3.0"
BUILD_NUMBER="42"
SCHEME="DocxEdit"
CONFIG="Release"
ARCHIVE_PATH="./build/${APP_NAME}-${VERSION}.xcarchive"
EXPORT_PATH="./build/export"
DMG_PATH="./build/${APP_NAME}-${VERSION}.dmg"
APP_DMG_PATH="./build/${APP_NAME}-${VERSION}.app.dmg"

# 1. Archive (Universal)
xcodebuild archive \
  -project "${APP_NAME}.xcodeproj" \
  -scheme "${SCHEME}" \
  -configuration "${CONFIG}" \
  -archivePath "${ARCHIVE_PATH}" \
  -destination 'generic/platform=macOS' \
  ARCHS="arm64 x86_64" \
  ONLY_ACTIVE_ARCH=NO \
  CURRENT_PROJECT_VERSION="${BUILD_NUMBER}" \
  MARKETING_VERSION="${VERSION}" \
  CODE_SIGN_STYLE=Manual \
  CODE_SIGN_IDENTITY="Developer ID Application: <Team Name>"

# 2. Export .app
xcodebuild -exportArchive \
  -archivePath "${ARCHIVE_PATH}" \
  -exportPath "${EXPORT_PATH}" \
  -exportOptionsPlist ./ExportOptions.plist

# 3. Подпись и нотаризация (если не сделано на этапе export)
codesign --deep --force --verify --verbose \
  --sign "Developer ID Application: <Team Name>" \
  --options runtime \
  --timestamp \
  "${EXPORT_PATH}/${APP_NAME}.app"

# 4. Notarize
xcrun notarytool submit "${EXPORT_PATH}/${APP_NAME}.app.zip" \
  --keychain-profile "AC_PASSWORD" \
  --wait

xcrun stapler staple "${EXPORT_PATH}/${APP_NAME}.app"

# 5. Создание .app.zip
cd "${EXPORT_PATH}" && zip -r "${APP_NAME}-${VERSION}.app.zip" "${APP_NAME}.app" && cd -

# 6. Создание DMG (через create-dmg, brew install create-dmg)
create-dmg \
  --volname "${APP_NAME} ${VERSION}" \
  --volicon "./Resources/AppIcon.icns" \
  --background "./Resources/dmg-background.png" \
  --window-pos 200 120 \
  --window-size 600 400 \
  --icon-size 110 \
  --icon "${APP_NAME}.app" 175 200 \
  --hide-extension "${APP_NAME}.app" \
  --app-drop-link 425 200 \
  --eula "./Resources/LICENSE.txt" \
  "${DMG_PATH}" \
  "${EXPORT_PATH}/" || true

# Альтернатива DMG через hdiutil (если create-dmg не подходит)
hdiutil create -volname "${APP_NAME} ${VERSION}" \
  -srcfolder "${EXPORT_PATH}" \
  -ov -format UDZO \
  "${APP_DMG_PATH}"

# 7. SHA256
shasum -a 256 "${DMG_PATH}" "${APP_NAME}-${VERSION}.app.zip" > SHA256SUMS
```

> **Альтернатива для DMG:** скрипт `scripts/make-dmg.sh` в репозитории, единая точка входа.

### 8.3. Публикация релиза

1. **Создать git-тег** с версией:
   ```bash
   git tag -a v0.3.0 -m "Release 0.3.0 — Tables & Pictures"
   git push origin v0.3.0
   ```
2. **Слить `release/0.3.0` в `main` и `develop`.**
3. **Создать GitHub Release** через `gh` CLI:
   ```bash
   gh release create v0.3.0 \
     ./build/DocxEdit-0.3.0.dmg \
     ./build/DocxEdit-0.3.0.app.zip \
     ./build/SHA256SUMS \
     --title "DocxEdit 0.3.0 — Tables & Pictures" \
     --notes-file RELEASE_NOTES.md
   ```
4. **Обновить сайт/документацию** (если применимо).
5. **Объявить в каналах** (опционально — соцсети, рассылка, Reddit r/macapps, Hacker News).
6. **Записать в `CLAUDE.md`** факт выпуска релиза (дата, артефакты, ключевые изменения).

### 9.3. Скрипт автоматического обновления при релизе

`scripts/update-claude-md.sh` (запускается из CI после публикации релиза):

```bash
#!/usr/bin/env bash
set -euo pipefail

VERSION="${1:?Usage: $0 VERSION DATE CODENAME}"
DATE="${2:?Usage: $0 VERSION DATE CODENAME}"
CODENAME="${3:?Usage: $0 VERSION DATE CODENAME}"
CLAUDE_MD="CLAUDE.md"

# Заменяем «Текущий релиз»
# Заменяем «Последнее обновление»
# Добавляем строку в «История релизов»
# Коммитим и пушим (только если есть изменения)

# Пример sed-замены (упрощённо; рекомендуется — через yq/jq или Python):
python3 - <<PYEOF
import re, datetime
p = "${CLAUDE_MD}"
s = open(p, encoding="utf-8").read()
s = s.replace(
    "> Автоматически обновляется. Последнее обновление: <DATE>",
    f"> Автоматически обновляется. Последнее обновление: {datetime.date.today().isoformat()}"
)
# Добавление строки в таблицу истории
new_row = f"| {VERSION} | {DATE} | {CODENAME} | см. CHANGELOG | DMG, APP |"
s = re.sub(
    r"(\n## 5. История релизов\n.*?\n\|.*?\n\|.*?\n)",
    r"\1" + new_row + "\n",
    s,
    flags=re.DOTALL,
)
open(p, "w", encoding="utf-8").write(s)
PYEOF

git add CLAUDE.md
git commit -m "chore(release): update CLAUDE.md for v${VERSION}" || true
git push origin main
```

- `CLAUDE.md` — **единственный источник истины** о долговременной памяти проекта.
- Запрещено удалять или перезаписывать записи об уже выпущенных релизах.

## 12. Глоссарий

- **DOCX** — формат Office Open XML, текстовые документы, ZIP-архив с XML.
- **OOXML** — Office Open XML, общий термин для форматов Office 2007+.
- **Ribbon** — ленточная панель инструментов в MS Word для Windows. В приложении **не используется** (вместо неё — стандартные меню macOS + настраиваемые тулбары, как в Word для Mac).
- **HIG** — Human Interface Guidelines от Apple.
- **Corpus** — набор тестовых документов для проверки совместимости.
- **Round-trip** — цикл «открыть → отредактировать → сохранить → открыть в оригинальном приложении».
- **ADR** — Architecture Decision Record, запись об архитектурном решении.
- **RC** — Release Candidate, кандидат на релиз.
- **Developer ID** — сертификат Apple для распространения приложений вне Mac App Store.
- **Notarization** — процесс проверки приложения Apple на безопасность перед распространением.
- **Gatekeeper** — механизм macOS, проверяющий подпись и нотаризацию приложений.
